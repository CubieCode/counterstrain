# Content provenance

Policy: docs/DESIGN.md, "AI-generated content policy". Ledger: `docs/CONTENT-PROVENANCE.md`. All AI-generated player-facing content must be documented and replaceable in the art and writing pass (P12.2).

**In scope:** textures, models, GUI art, particles, sounds, icons and logos, lang strings and item/block descriptions, quest titles and text, lore and field journal entries, in-world signs or books, mod/pack metadata shown to players, and store page copy and images. **Out of scope:** code, build files, scripts' comments and internal docs (ROADMAP, ARCHITECTURE, skills, READMEs for developers).

**When to add or update rows:** in the same PR that adds, changes, moves or removes in-scope content, whoever made it. One row per asset file; for text inside larger files, one row per quest ID or text block, and exactly one row per lang key (`mod/src/main/resources/assets/remission/lang/en_us.json:block.remission.nidus`): each key needs its own description, so new lang keys never get a shared `*` row. Write text IDs as `file:key` so the docs check can resolve the path. Use the section for the content type. When one key of a shared `*` row gets a different origin or status, give it its own exact-key row (`file:full.key`) below the `*` row and leave the `*` row as it is: the most specific row wins. Two rows for the same exact ID are an error.

**Row format:** `| Path / ID | Type | Origin | Status | Notes |`.
- Origin: `ai (<tool/model>)` when known, else `ai (model not recorded)`; `procedural (<script path>)`; `human (<who>)`; `licensed (<source>, <license>)`.
- Status: `placeholder` (stand-in, must be replaced), `draft` (usable, needs review or rework), `final` (accepted), `removed` (file deleted, or for a `file:key` row the key deleted from its file; the notes say when and why).
- Notes: what the art or writing pass should aim for (palette, mood, scale, voice), plus review records. For a lang key the notes are the writer's brief, shown in the content editor: what the string is, where the player sees it, constraints (length, glossary terms) and, for strings with arguments, `Args: %1$s <meaning>, %2$s <meaning>.` Never quote or suggest the wording itself.

**Placeholder markers:**
- Block, item and entity textures: a 2×2 pixel `#FF00FF` square in the top-left corner of a 16×16 texture, scaled proportionally for larger ones (4×4 at 32×32, 8×8 at 64×64). Draw it last, on top of the art; keep alpha 255. It is not the black/magenta missing-texture checkerboard.
- GUI art, icons, logos, gallery and promo images: a visible "PLACEHOLDER" label or watermark. HUD sprites too small for a label (the 9×9 viral load icon) take the texture marker instead and a `texture` row, so the check covers them.
- Sounds: no audible marker; the ledger row is the record.
- Lang strings: the value is the key itself, plus ` %1$s %2$s …` (positional and ascending, matching the indices the code passes, conversion kept) when the string takes arguments, e.g. `"commands.remission.cleanse.success.single": "commands.remission.cleanse.success.single %1$s"`. The row is `procedural (key as value)`, status `placeholder`. Agents never write English lang text: a new key is added as its placeholder with a described row, and a human writes the string in the content editor. The arguments in the placeholder are what the editor's argument check holds the human's string to.
- A marker on a `final` row, or no marker on a `placeholder` row, is a bug. `tools/check-provenance.sh` enforces this for `texture` and `lang` rows; check GUI labels by eye in harness screenshots (visual-checks).

**Replacing a placeholder or draft:** use `tools/content-editor.sh` (docs/DEV-ENVIRONMENT.md, "Content editor"): it checks uploads, edits `en_us.json` in place, updates or splits rows, records reviews, runs the checks below and opens a draft PR from a `content/<date>-<slug>` branch. By hand: replace the file in place (same path) or update the text, remove the marker from final art, then edit the existing row: new origin, new status, a note with what changed. Never delete the row. Accepting AI text or art unchanged as final needs a recorded human review in the notes (`accepted as final by <who>, <date>`); a lang key placeholder is never accepted as final. Replacing a lang placeholder keeps the row's notes (the brief) and sets origin `human (<who>, <date>)`. Moved or deleted assets keep their row with a note.

**The check:** `tools/check-provenance.sh`, a wrapper for `tools/check-provenance.py` (standard library only; CI: `docs.yml`; `--verbose` prints the asset count, `--self-test` runs the fixtures in `tools/tests/provenance/`). It fails when:
- an asset in a scanned tree has no row whose Path / ID is exactly its repository path. Scanned trees: `mod/src/main/resources/assets/`, the generated `assets/` tree under `mod/src/generated/resources/` (datagen models need rows too, origin `procedural (datagen)`) and `pack/` except `pack/mods/`; gitignored files are skipped. Assets: images (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`), sounds (`.ogg`, `.wav`, `.mp3`, `.flac`) and models (any `.json` under `assets/<namespace>/models/`, plus `.obj`, `.bbmodel`, `.geo.json`). Configs, scripts, blockstates, lang and packwiz TOML are not assets; text rows (`file:key`) never cover a whole asset file. Not scanned and not ledgered: `tools/visual-references/` (reviewed harness screenshots of the running game, used as test fixtures and never shipped; visual-checks) and `tools/tests/`.
- a `texture` row's PNG has the marker while `final`, or lacks it while `placeholder` (`draft` is not checked). The marker is a solid `#FF00FF`, alpha 255 square of `round(2 × width / 16)` pixels (2 at 16, 4 at 32, 8 at 64; animated strips use their width). PNGs must be non-interlaced. Rows of other types (gui, icon, particle) are not marker-checked.
- a row's file does not exist and its status is not `removed`, or a `removed` row's file still exists (for a `file:key` row: its JSON file still has the key, or a key with the prefix of a `*` row). Only Path / IDs under `mod/`, `pack/` or `docs/` are treated as files; store-page IDs are not.
- a status is not one of the four above, or two rows name the same asset file or the same text ID (an exact key row next to a matching `*` row is fine).
- a key in a lang file (`assets/<namespace>/lang/*.json` in a scanned tree) has no row, exact or `*`.
- a `lang` row's value disagrees with its status: `placeholder` but the value is not the key placeholder (the key, then ` %1$s %2$s …` in order), or `draft`/`final` but the value is still the key placeholder. Each key is judged by its most specific row.

**Checks before the PR:** `tools/check-provenance.sh` passes; every new lang key is a key placeholder with its own described row; harness screenshots of placeholder art show the marker. Mention the ledger rows in the PR body.
